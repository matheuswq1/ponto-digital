# Release v1.0.0-tolerance-summary

Tag Git: `v1.0.0-tolerance-summary` — estabilização do contrato de **tolerance summary** e da reconciliação em `meta.reconciliation`.

## O que mudou

- Contrato único `App\Contracts\ToleranceSummaryContract` com `RECONCILIATION_KEYS` e `orderedReconciliation()` (ordem fixa das chaves).
- Endpoint passa a montar `meta.reconciliation` via esse contrato (sem drift código/testes/docs).
- Fragmento OpenAPI em `docs/api/tolerance-summary-openapi.yaml` alinhado ao contrato.
- Testes de invariantes, cenário de iterável inconsistente, compatibilidade agregada com snapshot futuro (`version` / `engine` v2 quando o formato weekday permanece compatível).
- Snapshot JSON de resposta (Spatie) isolado em commit próprio para revisão clara.

## O que garante

- Ordem estável de chaves em `meta.reconciliation`.
- Distinção semântica: `identity_holds` (partição interna / matemática dos buckets) vs. `reconciliation_complete` (consistência global do período).
- Contagem explícita de linhas sem snapshot utilizável (`rows_without_snapshot`).
- CI executa `php artisan test` sem atualização automática de snapshots.

## Como evoluir

1. **Motor de snapshot (v2+)**: alterar `version`/`engine` em `tolerance_snapshot`; manter ou documentar quebra de formato; estender testes de agregação.
2. **Contrato de resposta**: alterar `ToleranceSummaryContract`, OpenAPI e snapshots em conjunto; para mudança compatível que quebra clientes, nova tag major do contrato/API.
3. **Roadmap**: eventos no snapshot (`late_entry`, `early_exit`, `extra_exit`, …); modo debug comparando engines no mesmo endpoint.
